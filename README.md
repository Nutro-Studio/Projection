# Projection

Покрокова асиметрична 4X-стратегія для 2–4 гравців (hotseat). Фракції змагаються за 21 провінцію, витрачають золото на війська й споруди, ведуть бої на кубиках 3d4 у стилі Root. Перемагає той, хто першим набере 50 VP. Імперія, що втратила майже всі землі (менше 3 провінцій), не вибуває, а переходить у Партизани зі зміною правил (Ruleset Shift).

**Фракції:** Мілітанти (форти, армія), Зилоти (церкви, десятина, місіонери), Гільдії (торгівля), Партизани (повстання).

## Запуск

1. Відкрити папку проєкту через Unity Hub (Unity 6, версія в `ProjectSettings/ProjectVersion.txt`).
2. Відкрити сцену `Assets/Scenes/Prototype.unity` і натиснути **Play**.

### Керування в прототипі

- **Клік по провінції**: виділити її.
- **Фаза дій**: кнопки праворуч наймають юнітів і будують споруди у виділеній провінції.
- **Space** (або кнопка): перейти до фази руху / завершити хід.
- **Фаза руху**: виділити свою провінцію з військами, вибрати кількість юнітів і клікнути зелену сусідню провінцію. Вхід у ворожі війська запускає бій.

Сценарій для перевірки: найняти солдата за 3G у Bastion → Space → перемістити його в нейтральний Rustford (провінція захоплюється) → дійти до провінцій Зилотів і провести бій.

## Структура

```
Assets/
  Scenes/Prototype.unity        ігрова сцена прототипу (економіка, карта, рух, бій)
  Scenes/Prototype_CombatTest   тестова сцена бойової системи
  Scripts/Core/                 ігрова логіка на чистому C#
    Combat/                     Root 3d4: ICombatService, RootCombatService, CombatCoordinator
    Crisis/                     Ruleset Shift: CrisisDirector, IFactionRuleset
    Economy/                    Treasury, EconomyRules, EconomyService
    Map/                        Province, ProvinceGraph, StandardMap
    Units/                      Unit, MovementService
    Turns/                      TurnManager
    GameState.cs, Match.cs      стан партії та збирання систем докупи
  Scripts/Prototype/            тимчасовий IMGUI-інтерфейс (EconomyPrototype)
  Tests/Editor/                 NUnit-тести логіки (EditMode)
docs/                           правила архітектури та гайд з тестування
```

Логіка в `Core` не залежить від Unity, тому її можна тестувати окремо, а UI лише читає стан і викликає команди. Правила коду описані в `docs/architecture_engineering_guidelines.md`.

## Реалізовані системи

- **Казна**: золото не може піти в мінус, кожна операція записується в журнал (`Treasury.Ledger`). Є переказ між фракціями та обнулення казни для кризи.
- **Економіка**: дохід +1G за провінцію на початку ходу. Ціни з rulebook зібрані в `EconomyRules`: солдат 3G, місіонер 3G, форт 5G (+1 VP), церква 4G (+2 VP). Перевіряється, яка фракція що може купувати.
- **Церковна десятина**: кожен чужий юніт, що закінчує хід у провінції з церквою, платить 1G власнику церкви. Партизани звільнені.
- **Карта**: 21 провінція (сітка 7×3), Мілітанти 8 / Зилоти 8 / нейтральні 5, по 10G на старті. Є перевірка зв'язності і найкоротший шлях (для торгових маршрутів).
- **Рух**: лише в сусідню провінцію, кожен юніт раз за хід, лише у фазі руху. Військо захоплює порожню чужу провінцію, місіонер не захоплює. Сторона з більшими втратами відступає в сусідню свою провінцію, а якщо такої немає, гине.
- **Ходи**: Upkeep → Actions → Movement → Scoring, гравці ходять по черзі.

- **Бій**: рух передає зіткнення в `ICombatService` (`RootCombatService`), бонус форту береться з `IFactionRuleset.ReceivesFortificationBonus` захисника. Якщо гарнізон знищено повністю, атакуючий займає провінцію.

### Точки інтеграції

- `Faction.Ruleset`: поточний `IFactionRuleset` фракції; заміна рулсету змінює дохід і бонуси без зміни іншого коду.
- `MovementService.ProvinceCaptured`, `MovementService.CombatResolved`, `TurnManager.TurnEnding`: події для нарахування VP, UI бою та перевірки кризи (< 3 провінцій).
- `GameState.Log`: текстовий журнал подій для UI.

## Тести

Window → General → **Test Runner** → EditMode → Run All.

Тести покривають казну, ціни й обмеження фракцій, споруди, десятину, структуру карти, валідацію руху, захоплення, бій із фіксованими кубиками та порядок фаз.
